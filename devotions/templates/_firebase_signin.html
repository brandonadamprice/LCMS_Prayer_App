{# Progressive enhancement for the "Sign in/up with Google" button, plus the "Sign in with Apple" button. Include this in any page that has an button. The anchor keeps working exactly as before when JavaScript is unavailable; this script intercepts the click and signs in through Firebase Authentication (popup) instead, posting the ID token to the /auth/firebase session bridge. This is the flow that also works inside native app shells, where Google blocks its OAuth pages in embedded webviews. Failure policy (Google): any unexpected failure (config fetch, SDK load, blocked popup, bridge error) falls back to the legacy /login/google redirect, so the worst case is identical to the pre-Firebase behavior. A deliberately closed popup just resets the button, and a 409 from the bridge carries a real user-facing message, so neither falls through to the legacy flow. Native shell (Capacitor): sign-in goes through the OS-level flow via the FirebaseAuthentication plugin instead of the web popup, and failures NEVER fall back to /login/google -- Google refuses its OAuth pages inside webviews (disallowed_useragent), which is the whole reason the native path exists. Sign in with Apple (App Store Guideline 4.8 requires it because the app offers Google login): pages ship a [data-apple-signin] element hidden by default and this script reveals it in the iOS shell (native AuthenticationServices flow via the plugin) and in normal web browsers (Firebase popup flow -- needs the Apple provider fully configured in the Firebase console with a Services ID + key, see docs/capacitor-ios.md). Either route lands on the same Firebase account, so an account created on iPhone signs straight into itself on the web and vice versa. Deliberately still hidden in the ANDROID shell: its WebView can't host the popup flow and the plugin's Android Apple support needs extra config -- revisit if ever needed (Play does not mandate Apple sign-in). Apple has no legacy redirect flow, so its failures toast and reset, never falling through. Backend-wise Apple tokens use the same /auth/firebase bridge (see firebase_auth_logic.py for relay-email and missing-name handling). #}
